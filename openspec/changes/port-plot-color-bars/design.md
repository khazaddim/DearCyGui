## Context

`PlotColorBars` was implemented on `Game_Controller_Build`:

- [`9812864`](https://github.com/khazaddim/DearCyGui/commit/9812864a54be9b24349fdd54a76a7d9d4d7b9cb0): initial implementation
- [`b6f4aa1`](https://github.com/khazaddim/DearCyGui/commit/b6f4aa1c4b5554b05a1ba03caf5b5852c9b10492): normalized mode

That branch was based on upstream `01d2ce7`. This worktree tracks upstream `main` (`3d13328`), which has since changed `plot.pyx` in `8777919` (Viewport variable refactor), `5f50063` and `89dea7f` (typed callback values), and `691509c` (pattern cache and callback fixes). It has also moved `core.pyi` to being generated by `stubs/stub_generator.py`.

A pre-port inspection of current upstream found that everything the original implementation depends on is still present:

- `plotElementXY` (`_X`, `_Y`, `_axes`, `_flags`, `_imgui_label`, `check_arrays()`)
- `DCG1DArrayView` typed access
- `parse_color` / `unparse_color`
- `PySequence_Check`
- the inline `cdef extern from * nogil` C++ block in `plot.pyx`
- the inherited `ignore_fit` property (`ImPlotItemFlags_NoFit`)

`PlotBars` itself is structurally unchanged, so the port should be close to mechanical. It is still done by hand-adapting the code, not by cherry-picking.

## Goals / Non-Goals

**Goals:**
- Recreate the observable behavior of the fork's `PlotColorBars` (data and normalized modes) on current upstream.
- Keep the change additive and contained to the plot module, the stubs, the docs, the tests and one demo.
- Use this port to prove the build → test → demo validation loop for this worktree.

**Non-Goals:**
- Multi-controller or gamepad support (a separate, later change).
- Changing `PlotBars` or any other existing plot item.
- New features beyond the fork, such as rounded corners, gradients or hover/picking.
- Upstreaming to DearCyGui/DearCyGui (possible later; out of scope here).

## Decisions

1. **Custom draw loop via `implot.BeginItem` / `GetPlotDrawList`, not `implot.PlotBars`.**
   ImPlot's `PlotBars` supports neither per-bar colors nor edge anchoring. A custom loop inside `BeginItem`/`EndItem` keeps legend, theme and visibility integration, and it can read `GetPlotLimits()` in the same pass.
   - *Alternative:* `DrawInPlot` with Python-built rectangles. Rejected because it lags one frame on pan and zoom, and it does not behave like a plot item.

2. **Resolve anchors and normalized length at draw time.**
   `resolve_anchor_value(limits, horizontal, anchor_mode, anchor_value)` and `length * fraction * span` are computed per frame from `implot.GetPlotLimits(self._axes[0], self._axes[1])`. This is what makes the frame-synchronous requirement hold. Python only stores enums and doubles.

3. **Store colors as `DCGVector[int32_t]` with 0/1/N broadcast semantics.**
   This matches the original layout. An empty vector means "use the theme color" for fills and "no border" for lines. Parsing goes through the existing `parse_color`, so every color format DearCyGui accepts works.

4. **Validate eagerly in property setters.**
   `_validate_configuration()` runs after every setter and raises `ValueError`. When one of `X`/`Y` is still empty, it skips the length checks, so properties can be assigned in any order during construction.

5. **Theme defaults from the ImPlot item data.**
   Two small C++ helpers, `GetCurrentItemColorU32(idx)` and `GetCurrentItemLineWeight()`, are added to the existing extern block. They read `ImPlot::GetItemData()` so the bars follow theme fill, line color and line weight.

6. **Generate `core.pyi` with `stubs/stub_generator.py` after the build.**
   The original branch hand-edited `core.pyi`. Upstream now generates it, so it will be regenerated from the built module. The resulting diff must be reviewed so that it contains only `PlotColorBars` changes.
   - *Fallback:* if the generator produces unrelated churn because of environment differences, hand-insert the `PlotColorBars` stub next to `PlotBars`, following the generated style, and note this in the commit message.

7. **Use a fresh focused test file, not a copy of `test_fork_regressions.py`.**
   Adapt the 25 PlotColorBars cases from `471ba7d:tests/test_fork_regressions.py` into `tests/test_plot_color_bars.py`. Use this repo's fixture cleanup: `C.queue.shutdown(wait=True)`, `C.viewport.destroy()`, `gc.collect()`. Gamepad cases are left for the controller change.

8. **Demo provenance.**
   First copy `PlotColorBars_Demo.py` unchanged from `Game_Controller_Build` (`9db7a6b`) in its own commit. Then adapt it in a separate commit if upstream's viewport/context API changes (`8777919`) require it, so the diff shows exactly what had to change.

9. **Exclude color bars from axis fitting in every mode.**
   `PlotColorBars` does not contribute bounds to either axis during continuous autofit or a one-time fit request. This applies to both orientations, all anchors, and both value spaces, even when `ignore_fit=False`. Keep the inherited property's defaults and getter/setter behavior for compatibility, but document that setting it to `False` does not enable fitting for this series. Do not add `FitPoint` calls or another fitter.
   Edge anchors and normalized lengths depend on the visible axis limits. Feeding their bounds back into fitting could create a feedback loop, including range drift from fit padding. Applying one non-fitting rule to every mode avoids mode-dependent behavior and preserves the fork. Any future fitting support requires a separate design.

## Risks / Trade-offs

- **Upstream refactors broke an assumption the inspection missed** (for example, `BeginItem` signature or `_flags` semantics) → The Cython build fails loudly. Fix in place, mirroring how `PlotBars` and `PlotStairs` currently call ImPlot.
- **Baseline/data-mode bars can be clipped by fitted ranges.** Color bars intentionally do not affect fitting, including when `ignore_fit=False`. Other fitting-enabled series or explicitly configured axis limits determine the view. Document this limitation and test exclusion from both axes rather than silently adding fitting.
- **Normalized mode with a log or time axis scales by raw limit span** → Accepted, as in the original. Document that normalized mode assumes linear value axes.
- **Generated `.cpp` files are not gitignored in this worktree** → Do not stage `dearcygui/*.cpp` generated by Cython. Only the hand-written backend `.cpp` files stay tracked.
- **Stale archive relink on Windows** (`setup.py` lacks `depends=[sdl3_lib, FT_lib]`) → This port does not touch SDL or FreeType, so it is low risk. If odd link behavior appears, use `--force-reinstall --no-cache-dir` per the build skill.

## Migration Plan

Additive only; there are no migrations. To roll back, revert the change commits.
