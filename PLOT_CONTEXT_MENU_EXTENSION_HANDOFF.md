# DearCyGui Plot Context-Menu Extension Handoff

## Status

Requested feature: allow a Python `dcg.Plot` host to add menu entries or submenus to the same native ImPlot right-click context menu used for axis, legend, settings, and plot options.

This is a custom DearCyGui feature. It requires changes in the custom DearCyGui Cython sources and in the vendored ImPlot C++ source.

No change is required in DearCyFi until the custom extension is implemented and rebuilt.

## Motivation

DearCyFi needs the following actions on a chart:

- Collapse Time
- Collapse Time Vec
- Restore Time

These actions should appear in the chart's existing right-click menu instead of requiring a separate demo-owned context menu or replacing DearCyGui's native plot menu.

The native menu currently loses this feature if it is replaced: fit, scale, legend, mouse-position, and crosshair entries are generated by ImPlot and are not accessible as Python widgets.

## Confirmed Existing Behavior

The custom build confirms:

- `dcg.Plot.menu_button` chooses the mouse button that opens ImPlot context menus.
- `dcg.Plot.no_menus` disables ImPlot context menus.
- Neither property exposes the native menu as a Python object.
- The native plot popup is opened and drawn inside ImPlot's `EndPlot()` implementation.
- The native popup ID is `##PlotContext`.
- The native popup content is created by `ShowPlotContextMenu()` in the vendored ImPlot source.
- Existing DearCyGui `dcg.Menu` and `dcg.MenuItem` widgets already support drawing nested menu content and queued callbacks.
- `dcg.MenuItem` callbacks are queued rather than executed during rendering.

Relevant files:

- `thirdparty/implot/implot.cpp`
- `thirdparty/implot/implot_internal.h`
- `thirdparty/implot/implot.h`
- `dearcygui/wrapper/implot.pxd`
- `dearcygui/plot.pyx`
- `dearcygui/plot.pxd`
- `dearcygui/widget.pyx`
- `setup.py`

## Proposed Scope

Implement one native plot-canvas context-menu extension for the first version.

The custom entries shall be rendered inside the existing `##PlotContext` popup after ImPlot renders its native entries:

- X-Axis submenu
- Y-Axis submenu
- Legend submenu
- Settings submenu
- Subplots submenu, when applicable

The feature may be disabled with existing `dcg.Plot.no_menus=True`.

The first version does not need to add custom entries to separate X-axis, Y-axis, or legend popups. It should cover right-clicks on the plot canvas.

Axis and legend popup integration can be added later if a cross-menu API is needed.

## Recommended API

Use existing DearCyGui widget parenting instead of adding a separate callback string or menu-item registry.

Allow `dcg.Plot` to own widget children:

```python
with plot:
    with dcg.Menu(C, label="DearCyFi") as dearcyfi_menu:
        dcg.MenuItem(
            C,
            label="Collapse Time",
            callback=lambda sender, target, data: chart.collapse_time_chart(
                sender, target, data
            ),
        )
        dcg.MenuItem(
            C,
            label="Collapse Time Vec",
            callback=lambda sender, target, data:
                chart.collapse_time_chart_vec(sender, target, data),
        )
        dcg.MenuItem(
            C,
            label="Restore Time",
            callback=lambda sender, target, data:
                chart.restore_time_chart(),
        )
```

No custom `context_menu_callback` API is required for the DearCyFi use case.

The existing `dcg.Menu` and `dcg.MenuItem` callback APIs supply:

- Submenu nesting
- Labels
- Enabled/check/shortcut properties
- Existing callback queueing
- Existing item state and GC behavior

Use existing native menu semantics for:

- `menu_button`
- `no_menus`
- native menu item ordering
- native menu close behavior

Do not replace `##PlotContext`.

## Alternative API

If the implementation team prefers explicit registration over widget parenting, add:

```python
plot.context_menu = [
    dcg.Menu(C, label="DearCyFi"),
]
```

or:

```python
plot.context_menu_callback = callback
```

The static widget-child design is preferred. It reuses existing widget state and callback behavior and avoids per-frame Python object creation.

## C++/ImPlot Changes

### 1. Add a callback type

In `thirdparty/implot/implot.h`, add a public callback typedef:

```cpp
typedef void (*ImPlotContextMenuCallback)(void* user_data);
```

No callback-specific return value is needed.

The callback is only used while the native plot context popup is open.

### 2. Add a SetNext API

In `thirdparty/implot/implot.h`, expose:

```cpp
IMPLOT_API void SetNextPlotContextMenuCallback(
    ImPlotContextMenuCallback callback,
    void* user_data);
```

In `thirdparty/implot/implot.cpp`, implement the pattern used by existing `SetNext*` APIs:

```cpp
void SetNextPlotContextMenuCallback(
    ImPlotContextMenuCallback callback,
    void* user_data)
{
    ImPlotContext& gp = *GImPlot;
    IM_ASSERT_USER_ERROR(
        gp.CurrentPlot == nullptr,
        "SetNextPlotContextMenuCallback() needs to be called before BeginPlot()!");
    gp.NextPlotContextMenuCallback = callback;
    gp.NextPlotContextMenuUserData = user_data;
}
```

### 3. Persist the callback on ImPlotPlot

Add to `ImPlotPlot` in `thirdparty/implot/implot_internal.h`:

```cpp
ImPlotContextMenuCallback ContextMenuCallback;
void* ContextMenuUserData;
```

Initialize these values to null in `ImPlotPlot()`:

```cpp
ContextMenuCallback = nullptr;
ContextMenuUserData = nullptr;
```

Add one-time next values to `ImPlotContext`:

```cpp
ImPlotContextMenuCallback NextPlotContextMenuCallback;
void* NextPlotContextMenuUserData;
```

Initialize and reset them with `GImPlot`.

### 4. Copy the next callback in BeginPlot

After ImPlot obtains or creates `ImPlotPlot` in `BeginPlot()`:

```cpp
plot.ContextMenuCallback = gp.NextPlotContextMenuCallback;
plot.ContextMenuUserData = gp.NextPlotContextMenuUserData;

gp.NextPlotContextMenuCallback = nullptr;
gp.NextPlotContextMenuUserData = nullptr;
```

The reset prevents stale callback pointers from leaking into later plots.

### 5. Invoke the callback in the native plot popup

The native popup is rendered in `EndPlot()`:

```cpp
if (ImGui::BeginPopup("##PlotContext")) {
    ShowPlotContextMenu(plot);
    ImGui::EndPopup();
}
```

After `ShowPlotContextMenu(plot)` returns, invoke the plot callback:

```cpp
if (plot.ContextMenuCallback != nullptr) {
    ImGui::Separator();
    plot.ContextMenuCallback(plot.ContextMenuUserData);
}
```

The separator is important: it visually separates native ImPlot entries from custom DearCyGui entries.

If no custom widgets exist, the callback should return without adding a separator.

### 6. Clear callback state safely

Clear persistent callback state after `EndPlot()` or when a plot is destroyed.

Do not store a Cython/Python object pointer after the Cython `Plot` object has been deleted. The user-data pointer is only expected to be valid for the active plot frame and must be cleared in `EndPlot()`.

## Cython/DearCyGui Changes

### 1. Expose SetNextPlotContextMenuCallback

Add the callback typedef and function to `dearcygui/wrapper/implot.pxd`.

The exact Cython declaration can follow existing ImPlot declarations:

```cython
ctypedef void (*ImPlotContextMenuCallback)(void*)

void SetNextPlotContextMenuCallback(
    ImPlotContextMenuCallback callback,
    void* user_data)
```

Use `noexcept`/Cython-compatible callback syntax if the project requires it for a C callback pointer.

### 2. Let Plot own widget children

In `Plot.__cinit__` in `dearcygui/plot.pyx`, add:

```cython
self.can_have_widget_child = True
```

This allows `dcg.Menu` and `dcg.MenuItem` objects to be parented by `dcg.Plot`:

```python
with dcg.Plot(C) as plot:
    with dcg.Menu(C, label="Application"):
        dcg.MenuItem(C, label="Action")
```

The exact parent assignment should continue through DearCyGui's existing `push_next_parent()` mechanism.

Do not call `draw_ui_children(self)` during normal plot drawing outside the native popup. The callback is responsible for drawing them only while `##PlotContext` is open.

### 3. Add a C callback bridge

In `dearcygui/plot.pyx`, define a C callback that reacquires the GIL and draws the plot's widget children:

```cython
cdef void draw_plot_context_menu(void* user_data) noexcept:
    with gil:
        cdef Plot plot = <Plot><PyObject*>user_data
        plot.draw_context_menu()
```

The implementation should use `draw_ui_children(plot)`, `imgui.GetCursorScreenPos()`, and the existing viewport position swap pattern already used for `Menu` and legend popups.

A sketch of the Cython method:

```cython
cdef void draw_context_menu(self) noexcept nogil:
    cdef Vec2 pos_w
    cdef Vec2 pos_p
    cdef Vec2 parent_size_backup

    if self.last_widgets_child is None:
        return

    pos_w = ImVec2Vec2(imgui.GetCursorScreenPos())
    pos_p = pos_w
    swap_Vec2(pos_w, self.context.viewport.window_pos)
    swap_Vec2(pos_p, self.context.viewport.parent_pos)
    parent_size_backup = self.context.viewport.parent_size
    self.context.viewport.parent_size = ImVec2Vec2(imgui.GetContentRegionAvail())

    draw_ui_children(self)

    self.context.viewport.window_pos = pos_w
    self.context.viewport.parent_pos = pos_p
    self.context.viewport.parent_size = parent_size_backup
```

This method must not create or delete widgets. It draws the existing widget children that are attached to the plot.

### 4. Register the callback before BeginPlot

Immediately before `implot.BeginPlot(...)` in `Plot.draw_item()`:

```cython
implot.SetNextPlotContextMenuCallback(
    <implot.ImPlotContextMenuCallback>draw_plot_context_menu,
    <void*>self)
```

Then call `BeginPlot()` normally.

This must happen every frame because ImPlot owns the next-plot setup state.

Do not register the callback if `no_menus=True`. It is harmless if `##PlotContext` cannot open, but skipping it is clearer.

### 5. Preserve thread and mutex safety

The C callback runs while DearCyGui is holding the plot draw mutex and ImGui/ImPlot context state.

Do not execute Python menu callbacks during the C callback. MenuItem's existing `draw_item()` code should continue to queue callback execution with `context.queue_callback(...)`.

Rules:

- The C callback reacquires the GIL only for drawing existing widget objects.
- Widget callback actions remain on the normal DearCyGui callback queue.
- Do not mutate plot data inside `MenuItem.draw()`.
- Lock child item mutexes only through the existing `draw_ui_children()` path.
- Restore viewport position/size state after drawing.
- Do not retain the C callback or Python object pointer after `EndPlot()`.

## Menu Entry Example

DearCyFi integration after DearCyGui support exists:

```python
with chart:
    with dcg.Menu(chart.context, label="DearCyFi"):
        dcg.MenuItem(
            chart.context,
            label="Collapse Time",
            callback=lambda *_args:
                chart.collapse_time_chart(debug=False),
        )
        dcg.MenuItem(
            chart.context,
            label="Collapse Time Vec",
            callback=lambda *_args:
                chart.collapse_time_chart_vec(debug=False),
        )
        dcg.MenuItem(
            chart.context,
            label="Restore Time",
            callback=lambda *_args:
                chart.restore_time_chart(),
        )
```

The callbacks are forwarded after the menu closes and use DearCyFi's existing methods.

The implementation should not add collapse logic to the DearCyGui C++ or Cython layer.

## Tests

### Unit Tests

Add tests in the custom DearCyGui test suite:

1. `Plot` accepts widget children.
2. `Menu` and `MenuItem` can be parented directly by `Plot`.
3. Removing the custom menu child removes it from the native popup.
4. `no_menus=True` does not render custom plot menu widgets.
5. The SetNext callback is reset after one plot frame.
6. Two plots in one window register independent menu children.
7. Switching or deleting one plot does not leave a dangling C callback pointer.
8. MenuItem selection queues and invokes its Python callback.
9. Nested `Menu` children draw and activate correctly.
10. Existing Plot GC tests still collect Plot, Menu, and MenuItem objects.

Add tests without a viewport for state ownership and parent linkage.

Do not add test-only branches to production rendering.

### Rendered Probe

Create a temporary script outside the committed demo first.

Use:

- `C.viewport.initialize(..., visible=False)`
- injected mouse position
- right-click inject/release
- several `render_frame()` calls for popup convergence
- no real mouse override

Verify:

1. Right-click on plot canvas opens native `##PlotContext`.
2. Native entries remain visible.
3. A separator separates native entries from custom entries.
4. A `DearCyFi` submenu is present.
5. The submenu contains Collapse Time, Collapse Time Vec, and Restore Time.
6. Selecting an item invokes its callback once.
7. Closing/reopening the popup does not duplicate menu entries.
8. Switching to a second plot shows that plot's custom entries only.
9. `no_menus=True` does not open the native popup or custom entries.
10. `menu_button` still controls native/custom popup activation.

Retained probe scripts are useful for native crashes:

1. `tmp_bare_window.py`
2. `tmp_plotcolorbars_minimal.py`
3. a new plot context-menu probe
4. the full DearCyGui demo

Run the smallest probe first after rebuilding.

## Manual Acceptance

Before declaring the feature complete:

- Native ImPlot context-menu entries are unchanged.
- A custom submenu appears in the native plot context popup.
- Native popup close behavior is unchanged.
- Right-click uses the existing `menu_button`.
- `no_menus=True` suppresses both native and custom menu content.
- Switching plots does not cross-display menu entries.
- Menu callbacks fire once.
- Deleting or replacing Plot/menu widgets does not crash or leave stale entries.
- The custom build can be rebuilt and reinstalled from source.

## DearCyFi Integration

After this feature exists in the custom build:

1. Add menu setup to `DearCyFi.__init__()`.
2. Create `dcg.Menu(label="DearCyFi")` as a child of the `DearCyFi` plot.
3. Add `Collapse Time`, `Collapse Time Vec`, and `Restore Time` `dcg.MenuItem` children.
4. Call existing DearCyFi methods:
   - `collapse_time_chart(debug=False)`
   - `collapse_time_chart_vec(debug=False)`
   - `restore_time_chart()`
5. Preserve direct Python API compatibility.
6. Keep the existing DearCyFi demo buttons as optional host controls.
7. Add README documentation.
8. Add focused DearCyFi tests for setup and callback routing.

Do not let DearCyFi modify `no_menus` or `menu_button` unless explicitly required. The extension should honor the host's existing plot configuration.

## Acceptance Criteria

The feature is complete when:

- `dcg.Plot` can own static `dcg.Menu`/`dcg.MenuItem` widget children.
- Custom menu entries are drawn inside the native ImPlot `##PlotContext` popup.
- Native ImPlot menu entries remain present.
- Custom entries can be nested submenus.
- Existing MenuItem callbacks execute once and do not execute during C++/ImGui rendering.
- `no_menus=True` suppresses custom entries.
- Separate plots can own separate custom menu entries.
- No stale callback pointer or deleted Python object survives after plot destruction.
- The custom DearCyFi chart can attach Collapse/Restore actions without replacing or recreating the native menu.

## Suggested Implementation Sequence

1. Add ImPlot callback fields and public SetNext API.
2. Invoke callback at the end of `ShowPlotContextMenu()`.
3. Expose callback in `wrapper/implot.pxd`.
4. Let `Plot` own widget children.
5. Register the Cython bridge callback before `BeginPlot()`.
6. Implement the C callback and viewport position restore.
7. Add unit tests for ownership and callback lifetime.
8. Build and run bare-window/minimal-plot probes.
9. Add and verify a temporary native-menu-plus-submenu probe.
10. Integrate the DearCyFi menu in a later change.
